# Устройство проекта «Тропа»

«Тропа» — статическое React-приложение на TypeScript и Vite. Приложение сохраняет данные в браузере, а PWA-кэш обеспечивает офлайн-доступ к оболочке и локальному каталогу. Вход, серверная синхронизация, кабинет тренера и групповые занятия описаны в [дорожной карте](../tasks/plan.md).

## Структура репозитория

| Путь | Что здесь находится |
| --- | --- |
| [src/app](../src/app) | Точка входа, навигация, координация сохранения прогресса и черновика, обновление PWA |
| [src/pages](../src/pages) | Карта, профиль, каталог, история, дорожная карта, экран тренировки и итоги. Стили CSS Modules лежат рядом с компонентами |
| [src/features/workout](../src/features/workout) | Модель занятия, подходы и замены, отдых, разминка и заминка, валидация черновика, звуковой сигнал |
| [src/entities/program](../src/entities/program) | Программы, остановки, настройки, каталог Kinetic, подбор и инструкции к упражнениям |
| [src/entities/progress](../src/entities/progress) | Сохранённые занятия, расчёт следующей остановки, расписание, статистика, сравнение и импорт |
| [src/shared](../src/shared) | Общие стили, иконки, кнопки и поля формы, нормализация поиска и функции локальных дат |

`Button`, `Input`, `Checkbox` и `Select` находятся в [shared/ui/Controls.tsx](../src/shared/ui/Controls.tsx). Они используют нативные элементы и принимают их атрибуты. Подписи полей, валидация и расположение остаются частью экрана или формы.

Светлая и тёмная палитры заданы в [tokens.css](../src/app/styles/tokens.css). Выбор темы хранится в `tropa-theme` отдельно от тренировок и резервной копии. Приложение применяет палитру до первого рендера и обновляет её при смене системной темы, если выбран системный режим.

Заголовок экрана и ссылки переиспользуются через [PageTitle](../src/shared/ui/PageTitle.tsx) и [NavigationLinks](../src/shared/ui/NavigationLinks.tsx). [SetFields](../src/features/workout/SetFields.tsx) задаёт подписи, ограничения и чтение веса и повторов для маршрутной тренировки, свободного занятия и редактора истории.
| [scripts](../scripts) | Подготовка каталога и офлайн-сборки, исходник сервис-воркера |
| [public](../public) | Манифест PWA, иконки и лицензия каталога |
| [.storybook](../.storybook) и [.github/workflows](../.github/workflows) | Истории компонентов и публикация на GitHub Pages |
| [tasks](../tasks) | Дорожная карта, чек-лист и план монетизации |

Слои обращаются к нижележащим модулям через публичные экспорты. Для модели прогресса у программы есть отдельный вход [program/@x/progress.ts](../src/entities/program/@x/progress.ts). Общие цвета, фон, фокус и параметры движения заданы в [tokens.css](../src/app/styles/tokens.css).

## Навигация

[resolveRoute](../src/app/route.ts) разбирает hash. Такой подход позволяет публиковать приложение в подкаталоге GitHub Pages и открывать отдельные экраны по ссылке без серверных перенаправлений.

| Адрес | Экран |
| --- | --- |
| `#map` | Карта активного круга |
| `#workout` | Начатая тренировка. При отсутствии черновика открывается карта |
| `#free` | Ручная запись свободной силовой или прогулки |
| `#result/<round>/<stop>` | Итоги занятия на остановке |
| `#result/free/<id>` | Итоги свободного занятия |
| `#history` | Календарь, список и прогресс по упражнениям |
| `#history/<stop>`, `#history/dumbbell/<stop>` | История остановки стартового маршрута или программы с гантелями |
| `#catalog`, `#settings`, `#roadmap` | Каталог, меню настроек и публичные планы |
| `#settings/workout`, `#settings/schedule`, `#settings/equipment`, `#settings/profile`, `#settings/data` | Разделы настроек |

В URL номера остановок начинаются с 1, в данных и массивах программы — с 0. Сохраняй соответствие индексов и названий при расширении существующего маршрута, поскольку старые записи ссылаются на эти индексы.

## Модель занятия и расписания

Стартовый маршрут масштабируется по числу тренировок в неделю и числу недель. Программа с гантелями использует восемь силовых остановок с фиксированными шаблонами. Подбор стартовой силовой учитывает инвентарь, группы мышц и время. Разминка и заминка входят в бюджет занятия. Порядок упражнений и замены можно менять в активном плане.

Во время силовой модель хранит план, выбранное упражнение, записанные подходы и таймер. Запись подхода добавляет фактические данные и запускает отдых, если остаётся работа. Таймер хранит секунды и срок окончания в миллисекундах. По сроку можно восстановить остаток после перезагрузки. При продлении отдыха на паузе таймер остаётся на паузе.

Расписание хранит выбранные дни недели и дату начала. План строится для незавершённых остановок активного круга. Перенос ближайшей остановки задаёт исключение, последующие даты рассчитываются по выбранным дням после неё. Календарь сравнивает даты в часовом поясе устройства, а история хранит абсолютное время записи.

Пауза расписания скрывает плановые даты. При возобновлении точкой отсчёта становится текущий локальный день, а завершённые остановки учитываются при расчёте оставшихся дат.

Карта рисует рельеф и непрерывную линию на одном холсте. Маркеры остановок остаются HTML-элементами для доступных ссылок на историю. Прокрутка центрируется на ближайшей остановке, если ширина маршрута превышает ширину карты.

## Хранение, резервная копия и совместимость

| Ключ `localStorage` | Содержимое |
| --- | --- |
| `tropa-workouts-v1` | `Progress` с версией, активным кругом, историей, профилем и переносом ближайшего занятия |
| `tropa-workout-draft-v1` | Активный `Workout`, включая план, таймеры, подходы и незавершённые блоки |

`Session` хранит дату, круг, остановку, подходы, длительность и при наличии оценку нагрузки, кардио, массу тела и расчёт расхода. Записи новой программы содержат `program`, а свободные занятия — `freeId`. Для записей маршрута идентификатор составляют круг и остановка. Свободные занятия учитываются в календаре и статистике, а расчёт следующей остановки и расписание их пропускают.

Старые записи без новых полей читаются как записи стартового маршрута. Чтение локальной истории пропускает повреждённые записи и подходы. Импорт резервной копии проверяет записи строже, затем объединяет историю без повторного добавления того же занятия. Импортированные круги отделены от текущего круга, чтобы чужой индекс остановки случайно не открыл следующий костёр. При смене программы `savedRoutes` сохраняет номер прежнего круга, расписание и перенос ближайшей остановки. Номера сохранённых кругов учитываются при создании нового круга и импорте. Незавершённый черновик можно восстановить после перезагрузки, если он относится к текущей следующей остановке.

`templates` хранит названия и идентификаторы упражнений свободных тренировок. При объединении резервных копий шаблоны сверяются по идентификатору. Итоги недели считаются по локальным датам с понедельника. Последняя остановка завершённого круга сохраняет его длину в `roundTotal`, чтобы отчёт можно было открыть и после старта следующего круга.

Черновик свободной силовой хранится отдельно в `tropa-free-strength-draft-v1`. Он содержит идентификатор будущей записи, добавленные подходы и введённую длительность. После сохранения в истории черновик удаляется. Если удаление не удалось, при чтении истории идентификатор уже сохранённого занятия исключает восстановление черновика. Длительность свободной силовой записывается в `durationSeconds`, а `elapsed` остаётся `null`.

Заметки привязаны к упражнению в рамках одной тренировки. Редактирование даты сохраняет исходную дату записи для сопоставления со старыми резервными копиями. Удаление завершённой остановки текущего круга доступно после завершения или сброса черновика.

Событие `storage` обновляет открытые вкладки. Если сохранить итог не удалось, приложение оставляет активную тренировку для повтора. Прогресс из разных браузеров и адресов переносится резервной копией.

## Каталог и офлайн-сборка

Источником упражнений служит [Kinetic](https://github.com/kinetic-place/exercises-json). Переводы названий и техники хранятся в `kinetic.ru.json` и `kinetic.cues.ru.json`. При обновлении пакета дополни переводы по исходным ID и запусти:

```sh
node scripts/prepare-kinetic.mjs
```

Скрипт сверяет наличие названий и число подсказок, обновляет данные каталога и определяет требования к инвентарю через `kinetic-equipment.mjs`. Текст техники загружается отдельно от основного кода. Лицензия MIT находится в [public/kinetic-license.txt](../public/kinetic-license.txt).

`npm run build` собирает `dist/`, затем `prepare-offline.mjs` формирует `sw.js` со списком ресурсов и хешем сборки. Сервис-воркер предварительно кэширует оболочку и файлы этой версии. Внешние видео остаются сетевыми. `useAppUpdate` откладывает активацию запрошенного обновления, пока открыто занятие.

## Разработка и публикация

GitHub Actions использует Node.js 22. Из корня проекта:

```sh
npm ci
npm run dev
```

| Команда | Назначение |
| --- | --- |
| `npm run check` | Форматирование, ESLint, Stylelint, TypeScript и Vitest |
| `npm run build:check` | Проверочная сборка и сервис-воркер в `.build-check/` |
| `npm run build` и `npm run preview` | Локальная проверка production-версии |
| `npm run storybook` | Просмотр карты, тренировки и истории в разных состояниях |
| `npm run build-storybook` | Сборка статического каталога компонентов |

Перед коммитом Husky запускает `check` и `build:check`. Для проверки офлайна открой production-превью онлайн, дождись готовности, затем отключи сеть и перезагрузи страницу. Для изменений в тренировке проверь сохранение подхода, паузу и перезагрузку, завершение занятия и появление записи в истории. На телефоне проверь горизонтальную прокрутку карты и переходы по клавиатуре.

Workflow [pages.yml](../.github/workflows/pages.yml) собирает приложение на push в `main` и публикует `dist/`. В репозитории должен быть выбран источник **GitHub Actions** в разделе **Settings → Pages**. После публикации проверь открытие адреса Pages, офлайн-готовность и прямую ссылку на историю.
